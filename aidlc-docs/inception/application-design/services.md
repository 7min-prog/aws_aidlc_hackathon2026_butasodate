# Services

## サービス定義とオーケストレーション

---

### RecordingService
- **責務**: 不健康行動の記録とポイント計算のオーケストレーション
- **フロー**:
  1. 行動記録を保存（Records テーブル）
  2. カテゴリに応じたポイントを計算
  3. AvatarService.addPoints() を呼び出してアバター更新
  4. 結果（獲得ポイント、レベルアップ/進化有無）を返却

### AvatarService
- **責務**: アバターの状態管理（レベル、進化、退化）
- **フロー（ポイント加算時）**:
  1. 累計ポイント更新
  2. レベルアップ判定（閾値チェック）
  3. 進化条件判定（レベル + カテゴリ比率）
  4. スキル習得判定
  5. アバター状態を保存
- **フロー（ポイント減算時）**:
  1. 累計ポイント更新
  2. レベルダウン判定
  3. 退化条件判定（進化条件を満たさなくなったか）
  4. スキル喪失処理
  5. アバター状態を保存

### HealthSyncService
- **責務**: ヘルスデータの同期と不健康/健康行動の自動検出
- **フロー**:
  1. クライアントからヘルスデータ受信
  2. 前回同期データとの差分計算
  3. 各カテゴリの基準値と比較して行動検出
  4. 不健康行動 → RecordingService経由でポイント加算
  5. 健康行動 → AvatarService.deductPoints() でポイント減算
  6. 検出結果サマリーを返却

### BattleService
- **責務**: バトルのライフサイクル管理（マッチング〜結果確定）
- **フロー**:
  1. マッチメイキング（ランダム or フレンド招待）
  2. 準備フェーズ（スキル・アイテムセット）
  3. ターンループ（行動選択 → 実行 → 状態更新）
  4. 終了判定（HP0 / 時間切れ / 切断）
  5. 結果保存・ランキングポイント更新
- **状態管理**: DynamoDBでバトル状態を完全管理（サーバー権威型）

### SocialService
- **責務**: フレンド関係の管理
- **フロー**:
  1. フレンド申請の送信・受信管理
  2. 承認時に双方のフレンドリストを更新
  3. オンライン状態の管理（WebSocket接続情報から判定）

### AdminService
- **責務**: 管理画面向けのCRUD操作オーケストレーション
- **フロー**:
  1. ユーザー管理（CRUD + 停止/復活/論理削除）
  2. ゲームデータ修正（アバター状態の直接編集）
  3. マスターデータ管理（進化パス、スキル定義のCRUD）

---

## サービス間連携パターン

```text
RecordingService ──→ AvatarService（ポイント加算）
HealthSyncService ──→ RecordingService（不健康行動記録）
HealthSyncService ──→ AvatarService（健康行動によるポイント減算）
BattleService ──→ AvatarService（ステータス参照）
AdminService ──→ AvatarService（データ修正）
```

## 通信パターン

| パターン | 用途 |
|---------|------|
| 同期呼び出し（Lambda内） | サービス間の直接呼び出し（同一Lambda内） |
| WebSocket | バトルリアルタイム通信 |
| REST API | クライアント↔サーバー間の通常通信 |
