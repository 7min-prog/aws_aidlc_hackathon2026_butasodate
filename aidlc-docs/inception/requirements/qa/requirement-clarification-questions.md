## Q3への補足説明: バックエンド構成のメリット・デメリット

ご質問いただいた各選択肢のメリデメです：

| 構成 | メリット | デメリット |
|------|---------|-----------|
| **A) AWS サーバーレス** (Lambda + API Gateway + DynamoDB) | コスト効率が高い（使った分だけ課金）、スケーラビリティ自動、インフラ管理不要、AWSエコシステムとの統合が容易 | コールドスタートの遅延、DynamoDBの設計が独特（RDBと異なる）、ローカル開発がやや複雑 |
| **B) AWS コンテナ** (ECS/Fargate + RDS) | 柔軟な構成、RDBの使い慣れたSQL、長時間実行処理に適する | コスト高め（常時稼働）、インフラ管理が必要、スケーリング設定が必要 |
| **C) Firebase** | セットアップが最も簡単、リアルタイムDB標準搭載、認証が簡単、無料枠が充実 | AWSとの統合が限定的、大規模時のコスト増、ベンダーロックイン、カスタマイズ性が低い |

**ハッカソン向けの推奨**: リアルタイム対戦（Q6でB選択）を考慮すると、**Firebase**はリアルタイム機能が標準搭載で開発速度が最も速いです。一方、**AWS サーバーレス**はAWSハッカソンとの親和性が高く、WebSocket API（API Gateway）でリアルタイム対戦も実現可能です。

## Q12への補足説明: プロパティベーステスト（PBT）とは

**プロパティベーステスト**は、通常のテスト（特定の入力→期待する出力を確認）とは異なり、「このルールは常に成り立つはず」という**性質（プロパティ）**を定義し、ランダムな入力を大量に生成して検証するテスト手法です。

**例（ぶたアプリの場合）**:
- 「スコアは常に0以上である」→ どんな行動記録の組み合わせでも成り立つか検証
- 「アバターの進化レベルは下がらない」→ ランダムなイベント列で検証
- 「バトルの勝敗判定は対称的である」→ AvsB と BvsA で矛盾しないか検証

**ハッカソンでは通常不要**です。開発速度を優先する場合はスキップが推奨です。
