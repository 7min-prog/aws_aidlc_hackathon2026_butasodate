# 要件定義書: ぶた育成ヘルスケアゲームアプリ

## Intent Analysis

- **User Request**: 不健康な行動をポジティブに記録する逆転発想の"ぶた"育成ヘルスケアゲームアプリの開発
- **Request Type**: New Project（新規プロジェクト）
- **Scope Estimate**: System-wide（複数コンポーネントにまたがるフルスタックアプリ）
- **Complexity Estimate**: Complex（リアルタイム対戦、ヘルスデータ連携、AI生成アバター、複雑な進化システム）

---

## 1. プロジェクト概要

「不健康な行動」をポジティブに記録できる逆転発想のヘルスケアゲームアプリ。深夜ラーメン、運動サボりなどの「ダメな行動」を記録すると、自分の分身である"ぶた"キャラクターが喜び、成長する。罪悪感なく記録したくなる仕組みにより、従来のヘルスケアアプリの継続率問題を解決する。

---

## 2. 技術スタック

| レイヤー | 技術 |
|---------|------|
| **フロントエンド** | Flutter（iOS / Android クロスプラットフォーム） |
| **バックエンド** | AWS サーバーレス（Lambda + API Gateway + DynamoDB） |
| **リアルタイム通信** | API Gateway WebSocket API |
| **認証** | Amazon Cognito（メール + ソーシャルログイン: Google, X） |
| **アバター生成** | AI生成画像 + AI生成短動画クリップ |
| **ヘルスデータ連携** | Apple HealthKit / Google Health Connect |
| **管理画面** | React（Web） |

---

## 3. 機能要件

### FR-1: ユーザー認証
- メールアドレス + パスワードによるサインアップ/ログイン
- ソーシャルログイン（Google, X）
- プロフィール管理（ニックネーム、アバター表示名）

### FR-2: 不健康な行動の記録
- **手動入力**: カテゴリ選択式の行動記録（深夜ラーメン、夜更かし、運動サボり等）
- **自動検出**: ヘルスデータからの不健康行動の自動検出（運動不足、体重増加、睡眠不足等）
- 記録履歴の閲覧・管理

### FR-3: ヘルスデータ連携
- Apple HealthKit / Google Health Connect との連携
- 取得データ:
  - 体重・BMI
  - 歩数データ
  - 睡眠データ（就寝・起床時刻、睡眠時間）
- 食事データは手動入力（FR-2で対応、ヘルスデータ同期は不要）
- スクリーンタイムは技術的制約により対象外
- 同期タイミング: 1日1回、アプリ初回起動時

### FR-4: ぶたアバター育成システム
- **複雑な進化システム**: 多数の進化パス、見た目 + ステータス + スキル
- 不健康な行動の記録に応じてアバターが成長・進化
- 体重・BMIが大きくなるほどアバターが進化
- AI生成画像による各進化段階のビジュアル
- AI生成短動画クリップによるアニメーション表現（進化時、バトル時等）
- スコアシステム（不健康度に基づくポイント）

### FR-5: リアルタイムバトルシステム
- ユーザー同士のリアルタイム対戦（同時接続）
- WebSocket による双方向通信
- マッチメイキング機能
- アバターのステータス・スキルに基づくバトルロジック
- バトル結果の記録・表示

### FR-6: ソーシャル機能
- フレンド機能（対戦相手の検索・追加）
- バトル履歴の共有

### FR-7: 管理画面（Web）
- **利用者**: 開発チーム（内部運用）
- **プラットフォーム**: Web アプリ（ブラウザアクセス）
- **ユーザー管理**: フル管理（一覧・検索・詳細閲覧・アカウント停止/復活・データ編集・削除・パスワードリセット）
- **ゲームデータ管理**: 閲覧 + マスターデータ管理（進化パス、スキル定義の編集）+ 個別ユーザーのゲームデータ修正
- **ダッシュボード**: 不要（データは別ツールで分析）
- **コンテンツ管理**: 不要
- **MVP**: 含める

## 4. 非機能要件

### NFR-1: パフォーマンス
- API レスポンスタイム: 500ms以内（通常操作）
- リアルタイムバトルのレイテンシ: 200ms以内
- アプリ起動時間: 3秒以内

### NFR-2: スケーラビリティ
- AWS サーバーレスによる自動スケーリング
- 同時接続バトルユーザー数: ハッカソンデモ規模（〜100人）

### NFR-3: 可用性
- ハッカソンデモ向け: 基本的な可用性確保

### NFR-4: ユーザビリティ
- 直感的なUI/UX（行動記録は3タップ以内）
- アバターの成長が視覚的にわかりやすい
- 日本語対応

### NFR-5: データプライバシー
- ヘルスデータのユーザー同意取得
- ヘルスデータはデバイスローカル + 暗号化して保存

---

## 5. MVP スコープ

ハッカソン向けMVPとして以下を含む：

1. **コア機能**: 不健康な行動の手動記録 + 自動検出 + アバター育成
2. **ヘルスデータ連携**: Apple HealthKit / Google Health Connect 統合
3. **バトルシステム**: リアルタイム対戦機能
4. **管理画面**: ユーザー管理 + ゲームデータ管理（Web）

### MVP外（将来対応）
- 詳細なランキングシステム
- SNS連携・シェア機能
- 課金・マネタイズ機能
- 多言語対応
