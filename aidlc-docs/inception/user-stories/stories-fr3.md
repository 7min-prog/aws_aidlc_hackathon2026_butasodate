# ユーザーストーリー: FR-3 ヘルスデータ連携

## 概要

- **対象機能**: FR-3 ヘルスデータ連携
- **分解アプローチ**: Feature-Based
- **粒度**: 細かめ（数時間〜1日）
- **受け入れ基準フォーマット**: Given-When-Then（BDD）
- **ペルソナ**: 一般プレイヤー（タケシ）
- **同期方式**: 1日1回、アプリ初回起動時に前日分を同期・評価。未起動日がある場合は前回起動時からの未評価期間分をまとめて加算。

---

### US-3.1: ヘルスデータ連携の初期設定（iOS）

**As a** 一般プレイヤー
**I want to** Apple HealthKitとの連携を有効にしたい
**So that** iPhoneのヘルスデータをアプリで活用できる

**受け入れ基準:**

- Given: iOS端末でアプリを初回起動した場合
  When: ヘルスデータ連携の設定画面を開く
  Then: Apple HealthKitへのアクセス許可ダイアログが表示される

- Given: HealthKitのアクセス許可ダイアログが表示された場合
  When: すべてのデータカテゴリへのアクセスを許可する
  Then: 連携ステータスが「連携中」に変わり、データの同期が開始される

- Given: HealthKitのアクセス許可ダイアログが表示された場合
  When: アクセスを拒否する
  Then: 連携ステータスが「未連携」のままとなり、手動記録のみ利用可能であることが案内される

### US-3.3: 体重・BMIデータの同期

**As a** 一般プレイヤー
**I want to** 体重・BMIデータを自動で同期したい
**So that** 体重変化がぶたの育成に自動反映される

**受け入れ基準:**

- Given: ヘルスデータ連携が有効な状態の場合
  When: その日の初回アプリ起動時に同期が実行される
  Then: 前回同期以降の最新の体重・BMIデータがアプリに取り込まれる

- Given: 体重・BMIが前回同期時より増加した場合
  When: 同期データが処理される
  Then: 不健康行動「体重増加」として検出され、ぶたの育成ポイントが増加する

- Given: 体重・BMIが前回同期時より減少した場合
  When: 同期データが処理される
  Then: 健康行動「体重減少」として検出され、ぶたの育成ポイントが減少する

- Given: 体重データが同期された場合
  When: 起動時サマリーが表示される
  Then: 「体重データが更新されました（+X kg / -X kg）」と表示される

### US-3.4: 歩数データの同期

**As a** 一般プレイヤー
**I want to** 歩数データを自動で同期したい
**So that** 運動量がぶたの育成に自動反映される

**受け入れ基準:**

- Given: ヘルスデータ連携が有効な状態の場合
  When: その日の初回アプリ起動時に同期が実行される
  Then: 前日分の歩数が集計されてアプリに取り込まれる

- Given: 数日間アプリを起動しなかった場合
  When: 久しぶりにアプリを起動して同期が実行される
  Then: 前回起動時から前日までの各日の歩数がそれぞれ集計・評価され、ポイントがまとめて加算される

- Given: 前日の歩数が目標値（デフォルト: 8,000歩）を下回った場合
  When: 同期データが処理される
  Then: 不健康行動「運動不足」として検出され、ぶたの育成ポイントが増加する

- Given: 前日の歩数が目標値（デフォルト: 8,000歩）を上回った場合
  When: 同期データが処理される
  Then: 健康行動「十分な運動」として検出され、ぶたの育成ポイントが減少する

- Given: 歩数データが同期された場合
  When: 起動時サマリーが表示される
  Then: 評価対象日ごとの歩数と結果（不健康/健康）が一覧表示される

### US-3.5: 睡眠データの同期（就寝・起床時刻）

**As a** 一般プレイヤー
**I want to** 就寝時刻と起床時刻を自動で同期したい
**So that** 生活リズムの乱れがぶたの育成に自動反映される

**受け入れ基準:**

- Given: ヘルスデータ連携が有効な状態の場合
  When: その日の初回アプリ起動時に同期が実行される
  Then: 前日の就寝時刻と起床時刻がアプリに取り込まれる

- Given: 就寝時刻がユーザー設定の基準値（デフォルト: 23:00）より遅い場合
  When: 同期データが処理される
  Then: 不健康行動「夜更かし」として検出され、基準値からのブレに応じたポイントが加算される

- Given: 就寝時刻がユーザー設定の基準値より早い場合
  When: 同期データが処理される
  Then: 健康行動「早寝」として検出され、基準値からのブレに応じたポイントが減算される

- Given: 起床時刻がユーザー設定の基準値（デフォルト: 7:00）より遅い場合
  When: 同期データが処理される
  Then: 不健康行動「寝坊」として検出され、基準値からのブレに応じたポイントが加算される

- Given: 起床時刻がユーザー設定の基準値より早い場合
  When: 同期データが処理される
  Then: 健康行動「早起き」として検出され、基準値からのブレに応じたポイントが減算される

### US-3.6: 睡眠データの同期（睡眠時間）

**As a** 一般プレイヤー
**I want to** 睡眠時間を自動で同期したい
**So that** 睡眠不足や寝すぎがぶたの育成に自動反映される

**受け入れ基準:**

- Given: ヘルスデータ連携が有効な状態の場合
  When: その日の初回アプリ起動時に同期が実行される
  Then: 前日の総睡眠時間がアプリに取り込まれる

- Given: 睡眠時間がユーザー設定の基準値（デフォルト: 7時間）より短い場合
  When: 同期データが処理される
  Then: 不健康行動「睡眠不足」として検出され、基準値からのブレに応じたポイントが加算される

- Given: 睡眠時間がユーザー設定の基準値以上かつ基準値+2時間未満の場合
  When: 同期データが処理される
  Then: 健康行動「十分な睡眠」として検出され、ポイントが減算される

- Given: 睡眠時間がユーザー設定の基準値+2時間以上の場合
  When: 同期データが処理される
  Then: 不健康行動「寝すぎ」として検出され、超過時間に応じて段階的にポイントが加算される

- Given: 睡眠時間がユーザー設定の基準値と一致する場合
  When: 同期データが処理される
  Then: ポイントの増減は発生しない

### US-3.7: 睡眠基準値のユーザー設定

**As a** 一般プレイヤー
**I want to** 就寝時刻・起床時刻・睡眠時間の基準値を自分で設定したい
**So that** 自分の生活スタイルに合った評価基準で判定される

**受け入れ基準:**

- Given: 設定画面のヘルスデータ連携セクションを開いた場合
  When: 睡眠基準値の設定項目が表示される
  Then: 就寝時刻基準（デフォルト: 23:00）、起床時刻基準（デフォルト: 7:00）、睡眠時間基準（デフォルト: 7時間）がそれぞれ設定可能である

- Given: 基準値を変更して保存した場合
  When: 次回の同期が実行される
  Then: 新しい基準値に基づいて評価が行われる

### US-3.8: データの同期（起動時同期）

**As a** 一般プレイヤー
**I want to** アプリ起動時にヘルスデータが自動同期されてほしい
**So that** 手動操作なしで最新データが反映される

**受け入れ基準:**

- Given: ヘルスデータ連携が有効な状態の場合
  When: その日の初回アプリ起動時
  Then: 前回同期以降のヘルスデータの同期が自動実行される

- Given: 同日中に2回目以降のアプリ起動をした場合
  When: アプリが起動する
  Then: 同期は実行されず、直接ホーム画面に遷移する

- Given: 数日間アプリを起動しなかった場合
  When: 久しぶりにアプリを起動する
  Then: 前回起動時から前日までの未同期期間のデータがまとめて同期・評価される

- Given: デバイスがオフラインの場合
  When: アプリを起動する
  Then: 同期はスキップされ、次回オンライン起動時に未同期データがまとめて同期される

---

### US-3.9: 起動時の同期サマリー表示

**As a** 一般プレイヤー
**I want to** アプリ起動時に自動検出された行動をまとめて確認したい
**So that** 前回起動以降に何が検出されたか把握できる

**受け入れ基準:**

- Given: 起動時同期で検出された行動（健康/不健康）がある場合
  When: アプリを起動する
  Then: 起動時サマリー画面に検出された行動の一覧（種類、日時、ポイント増減）が表示される

- Given: 起動時サマリーが表示された場合
  When: サマリーを確認して閉じる
  Then: ホーム画面に遷移し、ぶたの育成状態が更新されている

- Given: 起動時同期で検出された行動がない場合
  When: アプリを起動する
  Then: サマリー画面は表示されず、直接ホーム画面に遷移する

---

### US-3.10: 連携データカテゴリの個別設定

**As a** 一般プレイヤー
**I want to** 同期するデータカテゴリを個別にオン/オフしたい
**So that** 共有したくないデータは連携しないようにできる

**受け入れ基準:**

- Given: ヘルスデータ連携の設定画面を開いた場合
  When: データカテゴリ一覧が表示される
  Then: 各カテゴリ（体重・BMI、歩数、睡眠）ごとにオン/オフのトグルが表示される

- Given: 特定のデータカテゴリをオフにした場合
  When: 次回の起動時同期が実行される
  Then: オフにしたカテゴリのデータは同期されず、該当カテゴリの自動検出も停止する

- Given: オフにしていたデータカテゴリをオンに戻した場合
  When: 次回の起動時同期が実行される
  Then: 該当カテゴリの同期が再開され、未同期期間のデータは取り込まず再開タイミングからのみ同期する

---

### US-3.11: ヘルスデータ連携の解除

**As a** 一般プレイヤー
**I want to** ヘルスデータ連携を完全に解除したい
**So that** ヘルスデータの共有を停止できる

**受け入れ基準:**

- Given: ヘルスデータ連携が有効な状態で設定画面にいる場合
  When: 「連携を解除」ボタンを押す
  Then: 確認ダイアログが表示され、確認後にすべてのヘルスデータ同期が停止する

- Given: 連携を解除した場合
  When: 解除が完了する
  Then: アプリ内に保存されていた同期済みヘルスデータは保持され、以降の自動検出のみ停止する

- Given: 連携を解除した状態の場合
  When: 再度連携を有効にする
  Then: OS側のアクセス許可ダイアログが再表示され、許可後に同期が再開される

### INVEST基準の根拠

- **Independent（独立）**: 各ストーリーはプラットフォーム別設定、データカテゴリ別同期、UI表示、設定管理と独立して実装・テスト可能
- **Negotiable（交渉可能）**: 閾値（歩数目標、睡眠基準値等）やサマリー表示形式は調整可能
- **Valuable（価値がある）**: 各ストーリーが「不健康/健康行動の自動検出」というコア価値に直結
- **Estimable（見積可能）**: 各ストーリーは数時間〜1日で実装可能な粒度
- **Small（小さい）**: 1データカテゴリ = 1ストーリー、睡眠は就寝/起床と睡眠時間で分離
- **Testable（テスト可能）**: BDD形式の受け入れ基準により明確にテスト可能
