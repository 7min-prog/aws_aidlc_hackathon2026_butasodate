# NFR Requirements - Unit 3: アバター育成

## 1. パフォーマンス要件

| ID | 要件 | 目標値 | 根拠 |
|----|------|--------|------|
| PERF-1 | AvatarService.addPoints 応答時間 | 1秒以内 | ハッカソン規模、Unit 2 API内で呼び出し |
| PERF-2 | AvatarService.deductPoints 応答時間 | 1秒以内 | 同上 |
| PERF-3 | GET /avatar 応答時間 | 1秒以内 | ホーム画面表示時 |
| PERF-4 | 進化/退化演出再生時間 | 3-5秒（スキップ可能） | 演出重視、ユーザーが待てる範囲 |
| PERF-5 | スプライトシート初回読み込み | 制限なし | ハッカソン規模 |
| PERF-6 | Lambdaコールドスタート | 3秒以内 | Node.jsランタイム（Unit 1と同等） |

## 2. スケーラビリティ要件

| ID | 要件 | 目標値 | 根拠 |
|----|------|--------|------|
| SCALE-1 | 同時アバター更新リクエスト | 〜10人 | ハッカソンデモ規模 |
| SCALE-2 | DynamoDBキャパシティ | オンデマンド | 自動スケーリング |
| SCALE-3 | S3スプライトシート配信 | CloudFront不要 | デモ規模では直接S3アクセスで十分 |

## 3. 可用性要件

| ID | 要件 | 目標値 | 根拠 |
|----|------|--------|------|
| AVAIL-1 | アバターサービス稼働率 | AWSマネージドサービス依存 | Lambda + DynamoDB SLA |
| AVAIL-2 | スプライトシート取得失敗時 | フォールバック表示 | 初期段階のスプライトを表示 |
| AVAIL-3 | 進化判定失敗時 | ポイントのみ更新、進化は次回判定 | データ不整合防止 |

## 4. セキュリティ要件

| ID | 要件 | 実装方針 | 根拠 |
|----|------|----------|------|
| SEC-1 | アバターAPI認証 | Cognito JWT検証（Unit 1と同等） | 認証済みユーザーのみアクセス |
| SEC-2 | 他ユーザーのアバター操作防止 | userId = トークンのsub | 自分のアバターのみ操作可能 |
| SEC-3 | S3アセットアクセス | パブリック読み取り or 署名付きURL | スプライトシートは機密データではない |

## 5. テックスタック（Unit 3 固有）

| レイヤー | 技術 | 選定理由 |
|---------|------|----------|
| アバターDB | DynamoDB（オンデマンド） | Unit 1/2と統一、サーバーレス |
| アセット保存 | S3 | スプライトシートの静的ホスティング |
| アセットキャッシュ | flutter_cache_manager | DL/キャッシュ/有効期限を自動管理、将来のアセット追加に対応 |
| ゲームエンジン | Flame (Flutter) | スプライトシートアニメーション再生 |
| バックエンド | Lambda (Node.js 20.x) | Unit 1/2と統一 |
| IaC | AWS CDK (TypeScript) | Unit 1/2と統一 |

## 6. アセット管理方針

| 項目 | 方針 |
|------|------|
| スプライトシート形式 | PNG（スプライトシート） |
| 保存先 | S3バケット（`assets/sprites/` プレフィックス） |
| アセットサイズ | 制限なし（ハッカソン規模） |
| キャッシュ有効期限 | flutter_cache_managerデフォルト（7日） |
| フォールバック | キャッシュミス＆ネットワーク失敗時は初期スプライト表示 |
| アセット更新 | S3上書きで反映（キャッシュ期限切れ後に自動更新） |

## 7. 制約事項

- ハッカソンデモ規模のため、高パフォーマンス最適化は不要
- コスト最小化を重視（S3 + DynamoDB オンデマンド）
- 進化パスは初期リリースで6種固定（管理画面から追加は Unit 5 で対応）
- AI画像生成は事前生成済みアセットをS3に配置（リアルタイム生成なし）
