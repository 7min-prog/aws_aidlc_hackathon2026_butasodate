# NFR Requirements - Unit 1: 認証基盤

## 1. パフォーマンス要件

| ID | 要件 | 目標値 | 根拠 |
|----|------|--------|------|
| PERF-1 | ログイン/サインアップAPI応答時間 | 1秒以内 | ハッカソンデモ向け |
| PERF-2 | トークンリフレッシュ応答時間 | 500ms以内 | バックグラウンド処理のため緩め |
| PERF-3 | Lambdaコールドスタート | 3秒以内（初回） | Node.jsランタイムで達成可能 |
| PERF-4 | DynamoDBクエリ応答 | 100ms以内 | オンデマンドモードで十分 |

## 2. スケーラビリティ要件

| ID | 要件 | 目標値 | 根拠 |
|----|------|--------|------|
| SCALE-1 | 同時認証リクエスト数 | 〜10人 | ハッカソンデモ規模 |
| SCALE-2 | Cognito UserPool上限 | デフォルト制限内 | 追加設定不要 |
| SCALE-3 | DynamoDBキャパシティ | オンデマンド | 自動スケーリング、使った分だけ課金 |
| SCALE-4 | Lambda同時実行数 | デフォルト（1000） | デモ規模では問題なし |

## 3. 可用性要件

| ID | 要件 | 目標値 | 根拠 |
|----|------|--------|------|
| AVAIL-1 | 認証サービス稼働率 | AWSマネージドサービス依存 | Cognito SLA 99.9% |
| AVAIL-2 | データ永続性 | DynamoDB標準 | 3AZレプリケーション |
| AVAIL-3 | 障害時の挙動 | グレースフルデグラデーション | エラーメッセージ表示でUX維持 |

## 4. セキュリティ要件

| ID | 要件 | 実装方針 | 根拠 |
|----|------|----------|------|
| SEC-1 | パスワードポリシー | 8文字以上、大小英数字+記号 | Cognitoデフォルト |
| SEC-2 | トークン保存 | SharedPreferences | ハッカソン向け簡易実装 |
| SEC-3 | エラーメッセージ | 統一メッセージ（情報漏洩防止） | 「メールアドレスまたはパスワードが正しくありません」 |
| SEC-4 | レート制限 | Cognitoデフォルト（5回失敗で一時ロック） | 追加設定不要 |
| SEC-5 | アカウント停止時 | 次回APIアクセス時にログアウト強制 | シンプル実装 |
| SEC-6 | トークン有効期限 | Access: 1時間、Refresh: 30日 | Cognitoデフォルト |
| SEC-7 | 通信暗号化 | HTTPS必須（API Gateway標準） | TLS 1.2以上 |

## 5. テックスタック

| レイヤー | 技術 | 選定理由 |
|---------|------|----------|
| 認証 | Amazon Cognito | マネージド認証、OAuth対応、無料枠あり |
| API | API Gateway (REST) | Lambda統合、認証連携 |
| 関数 | AWS Lambda (Node.js 20.x) | コールドスタート短い、Cognito SDKとの相性良い |
| DB | DynamoDB (オンデマンド) | サーバーレス、自動スケーリング、使った分だけ課金 |
| フロントエンド | Flutter (Dart) | クロスプラットフォーム |
| 認証SDK | amplify_auth_cognito | Flutter公式Cognito連携 |
| トークン保存 | SharedPreferences | ハッカソン向け簡易実装 |
| IaC | AWS CDK (TypeScript) | インフラのコード管理 |

## 6. 制約事項

- ハッカソンデモ規模のため、高可用性・高スケーラビリティは優先しない
- コスト最小化を重視（AWS無料枠内で収まる構成）
- セキュリティはCognitoデフォルト設定を活用し、カスタム実装を最小化
- flutter_secure_storageは将来的なプロダクション移行時に検討

## 7. Q3補足: トークン保存方式について

アクセストークン（API認証用）とリフレッシュトークン（トークン更新用）をアプリ内に保存する必要がある。保存しないと毎回ログインが必要になる。

- **SharedPreferences**: 簡易保存。ハッカソンデモでは十分
- **flutter_secure_storage**: OS標準のKeychain/Keystoreを利用。プロダクション向け

今回はハッカソン規模のためSharedPreferencesを採用。
