# NFR Design Patterns - Unit 1: 認証基盤

## 1. レジリエンスパターン

### エラーハンドリング戦略
| レイヤー | パターン | 実装 |
|---------|---------|------|
| Flutter → API | リトライなし | 即エラー表示、ユーザーに再操作を促す |
| API Gateway → Lambda | タイムアウト | 29秒（API Gateway上限） |
| Lambda → Cognito | SDK標準リトライ | AWS SDK内蔵の指数バックオフ（変更不要） |
| Lambda → DynamoDB | SDK標準リトライ | AWS SDK内蔵の指数バックオフ（変更不要） |

### フォールバック
- Cognito障害時: エラーメッセージ「サービスが一時的に利用できません」を表示
- DynamoDB障害時: 認証自体はCognitoで完了、プロフィール取得のみ失敗扱い

## 2. パフォーマンスパターン

### コールドスタート
- **対策なし**（ハッカソンデモで許容）
- Node.js 20.xは比較的コールドスタートが短い（〜1秒）
- 初回アクセス時のみ遅延、2回目以降はウォーム状態

### Lambda最適化
| 項目 | 設定 |
|------|------|
| メモリ | 256MB（コスト/速度バランス） |
| タイムアウト | 10秒 |
| バンドルサイズ | 最小化（必要なSDKのみ） |

### フロントエンド
- トークンはメモリ内キャッシュ + SharedPreferences永続化
- トークン期限切れチェックはローカルで実施（APIコール不要）

## 3. セキュリティパターン

### 認証フロー保護
| 脅威 | 対策 |
|------|------|
| ブルートフォース | Cognitoデフォルト（5回失敗で一時ロック） |
| トークン漏洩 | Access Token 1時間有効期限 |
| 中間者攻撃 | HTTPS必須（API Gateway標準TLS 1.2） |
| 情報漏洩 | 統一エラーメッセージ |

### トークン管理フロー
```text
[アプリ起動]
    │
    ▼
SharedPreferencesからトークン読み込み
    │
    ├─ トークンなし → ログイン画面
    └─ トークンあり
         │
         ▼
    Access Token有効期限チェック（ローカル）
         ├─ 有効 → そのまま使用
         └─ 期限切れ → Refresh Token で更新
              ├─ 成功 → 新トークン保存、API呼び出し
              └─ 失敗 → ログイン画面へ遷移
```

## 4. コスト保護パターン

| 項目 | 設定 | 効果 |
|------|------|------|
| API Gatewayスロットリング | 100 req/sec | 意図しない大量リクエストをブロック |
| DynamoDBオンデマンド | 使った分だけ | 10人規模ならほぼ無料枠内 |
| Lambda | デフォルト同時実行 | 無料枠100万リクエスト/月 |
| Cognito | 無料枠 | 50,000 MAUまで無料 |
