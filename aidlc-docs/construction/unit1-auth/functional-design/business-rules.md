# Business Rules - Unit 1: 認証基盤

## BR-1: パスワードポリシー（Cognitoデフォルト）

| ルール | 条件 |
|--------|------|
| 最小文字数 | 8文字以上 |
| 大文字 | 1文字以上必須 |
| 小文字 | 1文字以上必須 |
| 数字 | 1文字以上必須 |
| 特殊文字 | 1文字以上必須 |

**バリデーションタイミング**: サインアップ時（フロントエンド即時 + Cognito側検証）

## BR-2: ニックネーム制約

| ルール | 条件 |
|--------|------|
| 最小文字数 | 2文字 |
| 最大文字数 | 10文字 |
| 使用可能文字 | 英数字、ひらがな、カタカナ、漢字 |
| 禁止文字 | 特殊文字、絵文字、空白のみ |
| 一意性 | システム全体でユニーク |
| 設定タイミング | 初回ログイン時に必須設定（スキップ不可） |

**バリデーション正規表現**: `^[a-zA-Z0-9\u3040-\u309F\u30A0-\u30FF\u4E00-\u9FFF]{2,10}$`

## BR-3: メール確認フロー

| ステップ | 動作 |
|---------|------|
| 1 | サインアップ時にCognitoが6桁確認コードをメール送信 |
| 2 | ユーザーがアプリ内で確認コードを入力 |
| 3 | コード一致でemailVerified = true |
| 4 | 確認完了までログイン不可 |

| ルール | 条件 |
|--------|------|
| コード有効期限 | 24時間（Cognitoデフォルト） |
| 再送回数制限 | Cognitoのレート制限に準拠 |
| 入力試行回数 | Cognitoのデフォルト（3回失敗でロック） |

## BR-4: ソーシャルログイン・アカウントリンク

| シナリオ | 動作 |
|---------|------|
| 新規Googleログイン（未登録メール） | 新規アカウント作成 → ニックネーム設定画面へ |
| 新規Xログイン（未登録メール） | 新規アカウント作成 → ニックネーム設定画面へ |
| Googleログイン（既存メール登録済み） | 既存アカウントに自動リンク → ホーム画面へ |
| Xログイン（既存メール登録済み） | 既存アカウントに自動リンク → ホーム画面へ |
| 2回目以降のソーシャルログイン | 既存アカウントでログイン → ホーム画面へ |

**自動リンク条件**: メールアドレスが一致する場合のみ

## BR-5: セッション管理

| トークン | 有効期限 | 用途 |
|---------|---------|------|
| アクセストークン | 1時間 | API認証 |
| リフレッシュトークン | 30日 | アクセストークン再取得 |
| IDトークン | 1時間 | ユーザー情報取得 |

| ルール | 動作 |
|--------|------|
| アクセストークン期限切れ | リフレッシュトークンで自動更新（ユーザー操作不要） |
| リフレッシュトークン期限切れ | 再ログイン必要 |
| ログアウト | リフレッシュトークン無効化 |

## BR-6: ログインエラーハンドリング

| シナリオ | エラーメッセージ | 理由 |
|---------|----------------|------|
| メール未登録 | 「メールアドレスまたはパスワードが正しくありません」 | セキュリティ（存在確認防止） |
| パスワード不一致 | 「メールアドレスまたはパスワードが正しくありません」 | セキュリティ |
| メール未確認 | 「メールアドレスの確認が完了していません」 | 確認フローへ誘導 |
| アカウント停止 | 「アカウントが停止されています」 | 管理者対応を促す |
| アカウント削除済み | 「メールアドレスまたはパスワードが正しくありません」 | セキュリティ |

## BR-7: 初回ログインフロー

| 条件 | 動作 |
|------|------|
| nickname未設定 | ニックネーム設定画面を表示（必須、スキップ不可） |
| nickname設定済み | ホーム画面へ遷移 |

**判定方法**: ログイン成功後、DynamoDBのUserレコードのnickname有無を確認
