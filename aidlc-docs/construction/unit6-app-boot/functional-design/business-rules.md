# Business Rules - Unit 6: 起動時処理

## BR-6.1: スプラッシュ最低表示時間
- スプラッシュ画面は最低1秒間表示する
- 起動処理が1秒未満で完了した場合、残り時間を待機してから遷移する
- 起動処理が1秒以上かかった場合、完了次第すぐに遷移する

## BR-6.2: トークン検証の優先順位
1. ローカルにトークンが存在しない → 即座にログイン画面
2. アクセストークンで `/users/me` を呼び出し
3. 401の場合、リフレッシュトークンで更新を試行
4. リフレッシュ失敗 → ローカルトークン全削除 → ログイン画面

## BR-6.3: プロフィール状態による遷移判定
| `/users/me` レスポンス | 遷移先 |
|---|---|
| 200 + nickname有り | 初期データ取得 → ホーム |
| 200 + nickname無し/空 | /nickname |
| 404 | /nickname |
| 401（リフレッシュ失敗後） | /login |

## BR-6.4: 初期データ取得の非ブロッキング原則
- 初期データ取得（avatar, summary, pending-requests）の失敗はホーム遷移をブロックしない
- 各データが取得できなかった場合、ホーム画面の該当セクションで個別にエラー/空表示する
- ヘルスデータ同期は完全にバックグラウンド（結果を待たない）

## BR-6.5: アバター自己修復
- `GET /avatar` が 404 を返した場合、`POST /avatar` で初期アバターを自動作成する
- 自動作成が失敗した場合、avatarデータ = null としてホーム画面に進む
- ホーム画面でアバターが null の場合、「アバターを作成」ボタンを表示する

## BR-6.6: ニックネーム設定時のアバター作成
- ニックネーム保存成功後、`POST /avatar` を呼び出す
- 失敗時は最大3回リトライ（1秒間隔）
- 3回失敗してもホーム画面に遷移する（起動時の自己修復 BR-6.5 に委ねる）

## BR-6.7: オフラインフォールバック
- ネットワークエラー時、ローカルキャッシュの存在を確認する
- キャッシュあり → キャッシュデータでホーム画面を表示（読み取り専用モード）
- キャッシュなし → エラー画面（「接続を確認してリトライ」ボタン）
- オフラインモード中は画面上部にバナーを表示する
- オフラインモード中は書き込み操作（記録追加等）を無効化する

## BR-6.8: キャッシュ更新ルール
- 起動時にAPIから正常取得できたデータは常にキャッシュを上書きする
- サマリーキャッシュは日付が変わったら無効とする
- ログアウト時にすべてのキャッシュを削除する

## BR-6.9: ヘルスデータ自動同期
- 起動時に端末のヘルスデータ（歩数、体重、睡眠）を取得し `POST /health/sync` に送信する
- 初期データ取得と並列で実行するが、結果は待たない（fire-and-forget）
- 同期失敗は無視する（次回起動時に再試行される）
- ヘルスデータ取得の権限がない場合はスキップする

## BR-6.10: アバター画像取得
- `GET /avatar` レスポンスの `spriteSheetKey` からS3 URLを構築する
- URL形式: `https://{ASSETS_BUCKET}.s3.ap-northeast-1.amazonaws.com/assets/{spriteSheetKey}.png`
- 画像はアプリのキャッシュディレクトリにローカル保存する
- キャッシュキーは `spriteSheetKey` のハッシュ値とする

## BR-6.11: 画像キャッシュ無効化
- `spriteSheetKey` が前回と異なる場合（進化/退化）、古いキャッシュを削除し新画像をダウンロードする
- ダウンロード失敗時はアプリバンドル内のデフォルト画像（プレースホルダー）を表示する
- ログアウト時に画像キャッシュも全削除する

## BR-6.12: 画像プリロードの非ブロッキング
- アバター画像のダウンロードはホーム遷移をブロックしない
- 画像ダウンロード中はプレースホルダーを表示し、完了後に差し替える
- キャッシュヒット時は即座に表示する
