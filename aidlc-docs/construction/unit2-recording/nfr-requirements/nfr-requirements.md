# NFR Requirements - Unit 2: 行動記録 + ヘルスデータ連携

## 1. パフォーマンス要件

| ID | 要件 | 目標値 | 根拠 |
|----|------|--------|------|
| PERF-1 | 行動記録API応答時間 | 500ms以内 | 記録→ぶた喜び演出の即時フィードバック |
| PERF-2 | ヘルスデータ同期API応答時間 | 3秒以内（通常）、5秒以内（7日分以上） | 起動時ローディング表示あり |
| PERF-3 | 記録履歴API応答時間 | 500ms以内 | DynamoDB Query（PK指定）で達成可能 |
| PERF-4 | サマリーAPI応答時間 | 500ms以内 | 当日/週間集計 |
| PERF-5 | Lambdaコールドスタート | 3秒以内（初回） | Node.js 20.xで達成可能 |
| PERF-6 | HealthKit/HealthConnect取得 | 10秒タイムアウト/カテゴリ | 超過時はスキップ→次回リトライ |

## 2. スケーラビリティ要件

| ID | 要件 | 目標値 | 根拠 |
|----|------|--------|------|
| SCALE-1 | 同時リクエスト数 | 〜10人 | ハッカソンデモ規模 |
| SCALE-2 | DynamoDBキャパシティ | オンデマンド | 自動スケーリング |
| SCALE-3 | 1ユーザーあたりレコード数 | 無制限（全履歴保持） | DynamoDB PK+SK設計で性能劣化なし |
| SCALE-4 | Lambda同時実行数 | デフォルト（1000） | デモ規模では問題なし |

## 3. データ整合性要件

| ID | 要件 | 実装方針 | 根拠 |
|----|------|----------|------|
| DATA-1 | 行動記録の冪等性 | recordId（UUID）で重複排除 | ネットワークリトライ対策 |
| DATA-2 | ヘルス同期の冪等性 | userId+syncDate+categoryで一意制約 | 二重処理防止 |
| DATA-3 | バッチ処理のアトミック性 | DynamoDB TransactWriteItems | 部分失敗防止 |
| DATA-4 | ポイント整合性 | レコード保存とポイント加算を同一トランザクション | 不整合防止 |
| DATA-5 | カテゴリマスターの一貫性 | サーバー側で最新basePointsで確定計算 | キャッシュ不整合対策 |

## 4. オフライン/同期要件

| ID | 要件 | 目標値 | 根拠 |
|----|------|--------|------|
| OFFLINE-1 | オフラインキャッシュ上限 | 50件 | 端末ストレージ節約 |
| OFFLINE-2 | キャッシュ超過時 | 古いPENDINGレコードから削除 | FIFO方式 |
| OFFLINE-3 | ネットワーク復帰検出 | Connectivity変更リスナー | 自動同期トリガー |
| OFFLINE-4 | バッチ同期リトライ | 最大3回（指数バックオフ） | 一時的障害対応 |
| OFFLINE-5 | ローカルDB | Hive | Pure Dart、セットアップ最小 |

## 5. 可用性要件

| ID | 要件 | 目標値 | 根拠 |
|----|------|--------|------|
| AVAIL-1 | API稼働率 | AWSマネージドサービス依存 | API Gateway + Lambda SLA |
| AVAIL-2 | データ永続性 | DynamoDB標準（3AZレプリケーション） | マネージド |
| AVAIL-3 | ヘルスAPI障害時 | カテゴリ別スキップ→次回リトライ | 部分失敗許容 |
| AVAIL-4 | バックエンド障害時 | オフラインモードで記録継続可能 | UX維持 |

## 6. セキュリティ要件

| ID | 要件 | 実装方針 | 根拠 |
|----|------|----------|------|
| SEC-1 | API認証 | Cognito JWT検証（Unit1で実装済み） | 全エンドポイントに認証必須 |
| SEC-2 | データアクセス制御 | userId = token.subのレコードのみ操作可 | 他ユーザーデータへのアクセス防止 |
| SEC-3 | ヘルスデータの取り扱い | サーバーには集計値のみ送信（生データ不送信） | 最小限のデータ転送 |
| SEC-4 | ローカルヘルスデータ | メモリ内処理、永続化しない | 端末内で完結 |
| SEC-5 | 通信暗号化 | HTTPS必須（API Gateway標準） | TLS 1.2以上 |

## 7. テックスタック（Unit2追加分）

| レイヤー | 技術 | 選定理由 |
|---------|------|----------|
| ヘルスデータ取得 | health パッケージ (Flutter) | HealthKit/HealthConnect統合、クロスプラットフォーム |
| ローカルDB | Hive | Pure Dart、セットアップ最小、ハッカソン向け |
| ネットワーク状態 | connectivity_plus | オフライン検出、復帰トリガー |
| ローカル設定 | SharedPreferences | HealthSyncSettings保存（Unit1と統一） |
| バックエンド | Lambda (Node.js 20.x) | Unit1と統一 |
| DB | DynamoDB (オンデマンド) | Unit1と統一 |
| トランザクション | DynamoDB TransactWriteItems | アトミック処理 |
| IaC | AWS CDK (TypeScript) | Unit1と統一 |

## 8. 制約事項

- ハッカソンデモ規模のため高可用性は優先しない
- コスト最小化（AWS無料枠内）
- HealthKit/HealthConnectの権限はユーザー任意（拒否時は手動記録のみ）
- ヘルスデータの生値（個別の歩数記録等）はサーバーに送らず、端末側で集計した結果のみ送信
